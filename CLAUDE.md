## 1. ARCHITECTURE ENFORCEMENT (NON-NEGOTIABLE)

RaceVeil is a single local Go CLI binary — no server, no database, no control
plane (Context/DECISIONS.md ADR-010, ADR-011). It still follows Clean
Architecture, adapted to Go idiom and to RaceVeil's actual component shape (a
verification pipeline, not a CRUD web service). Layer boundaries are
inviolable. Violations are defects, not style issues. Full component-to-layer
rationale: [`docs/SYSTEM_DESIGN.md`](docs/SYSTEM_DESIGN.md).

```
PRESENTATION   (internal/presentation/cli/, cmd/raceveil/)
  Owns:     Cobra command parsing, output serialisation (human/json/sarif),
            input validation, safe-mode confirmation prompts
  Must not: contain business logic, call internal/infrastructure directly,
            hold state, write to the run directory itself
  Calls:    internal/application ONLY, via internal/wiring

APPLICATION   (internal/application/{scheduler,oracle,minimize,discovery,ranking}/)
  Owns:     Experiment lifecycle orchestration, Oracle evaluation (Levels 1-5),
            Statistical Verification, Minimization, Candidate ranking/discovery
  Must not: perform raw socket/TLS I/O, know Cobra/CLI concepts, expose raw
            internal errors to callers without wrapping
  Calls:    internal/domain + internal/infrastructure (via interfaces)

DOMAIN   (internal/domain/)
  Owns:     Entities and value objects fixed by Design/DOMAIN.md: Target,
            Scope, Endpoint, Request, Workflow, Session, Invariant, Candidate,
            Experiment, Baseline, ConcurrentTrial, Observable, Evidence,
            Confidence, Severity, Finding, Reproduction — plus store
            INTERFACES for persistence
  Must not: import from any other layer, depend on any framework
  Has ZERO external dependencies — pure business logic.

INFRASTRUCTURE   (internal/infrastructure/{sync,persist,crawl}/, internal/security/scope/)
  Owns:     All I/O — the sync package (H2SinglePacket/H1LastByte), the
            filesystem run-directory writer, the crawler/HAR importer
            (Phase 3 stub), and the Scope/Authorization guard chokepoint
  Must not: contain use-case orchestration, call internal/application
  Implements: internal/domain store interfaces

# Dependency direction: Presentation -> Application -> Domain <- Infrastructure
```

**Deliberate exception, documented so it is never mistaken for a violation
later:** `internal/security/scope/` is infrastructure (it dials real sockets)
but encodes a business-critical safety rule (default-deny, IP pinning,
destructive-verb blocking). It is CORE_FILES for that reason
(docs/ARCHITECTURE_DECISIONS.md GOV-004), not because it breaks the layering.

**Not yet implemented, on purpose:** `internal/application/{discovery,ranking}/`
and `internal/infrastructure/crawl/` are Phase 3 / v1 capabilities
(docs/PRD.md §3). Their package shape exists now so the layering is right
from day one; do not build real logic into them until the MVP (Phases 0-2) is
done and a task explicitly calls for Phase 3 work.

```

module-to-test mapping with zero extra tooling, forever.

### 2.1 Universal Security Invariants (ABSOLUTE — NEVER NEGOTIATE)

```
- Credentials/secrets/keys NEVER written to any file on disk.
- .env is in .gitignore. Must never be committed.
- Raw exceptions/panics and stack traces NEVER returned to CLI output or reports.
- User-controlled input NEVER interpolated into shell commands or file paths
  without validation — RaceVeil has no SQL layer (docs/DB_SCHEMA.md), so the
  Guide's query-parameterisation invariant has no matching surface here.
- Secrets NEVER appear in log output at any level.
- Config/env access ONLY through internal/config — never raw os.Getenv in
  feature code.
```

**Project-specific invariants, layered on top of the universal set** (from
Design/SECURITY.md, load-bearing regardless of the "no compliance framework
required" answer in docs/ARCHITECTURE_DECISIONS.md GOV-005 — these exist for
product-safety reasons, not regulatory ones):

```
- Every outbound request passes through internal/security/scope.Guard —
  no request-sending code path may bypass it.
- Default-deny: only Scope-listed hosts/ports/path-prefixes are touchable.
- IP pinning: authorized hosts are resolved once and pinned for the run
  (anti-DNS-rebinding). Never re-resolve mid-run.
- Session secrets are redacted in every persisted artifact (config.yaml,
  audit.jsonl, trials, oracle output, reports, .rv findings) — the live
  in-memory Session is the only place they exist unredacted.
- .rv artifacts template secrets as ${ENV} placeholders; never embed a live
  credential in a finding.
- RaceVeil never exceeds proof.max_successful_effects to force a proof
  (Design/SECURITY.md §6) — an Experiment whose required_proof_effects
  exceeds the cap is refused as unprovable-under-cap, not overridden.
- No stealth, evasion, persistence, credential harvesting, privilege
  escalation, or automated destructive exploitation features, ever
  (Design/SECURITY.md §10) — a feature request in this direction is refused
  as out-of-charter, not implemented "behind a flag."
```

### 2.3 Boundary Caveats (Guide §2.3)

```
P1. PERMISSION MODE: never operate this repo with
    --dangerously-skip-permissions or defaultMode: bypassPermissions.

## 6. TESTING DISCIPLINE

Runner inferred per Guide §6.0 from `go.mod` — `go test ./... -count=1`
(covenantwin.py auto-detects this; do not hardcode a different runner).

```
Lint:        golangci-lint run ./...      (bundles go vet + staticcheck)
Format:      gofmt -l .                   (must produce no output)
Type-check:  go build ./...               (Go's compiler is the type checker)
Complexity:  gocyclo -over 10 .           (threshold 10, matches Guide §4.4 default)
Test:        go test ./... -count=1
Coverage:    go test ./... -count=1 -cover   (threshold 80%, Guide §4.4 default)
```

```
N1. Every new function in internal/application or internal/domain gets a
    unit test IN THE SAME TASK — named in the Phase 2 design declaration,
    before implementation exists.
N2. Every internal/infrastructure implementation gets an integration test.
N3. Mock at the internal/infrastructure interface boundary. Never deeper.
N4. go test ./... exits 0 before any task is complete.
N5. Never modify a test to make it pass.
N6. Runner is inferred (Guide §6.0), never hardcoded to a different stack.
```

**Oracle testing is CRITICAL, not incidental** (Design/TEST_PLAN.md Layer 3):
Oracle classification logic (`internal/application/oracle/`) is tested
against frozen fixtures in `testdata/oracle/` — recorded baseline +
concurrent-trial observations, no live network. A change to Oracle logic
without a corresponding fixture-based test is not complete, even if
`go test ./...` passes, because the fixtures are what prove the oracle
still separates a real violation from ordinary nondeterminism.

**Scaling rules (Guide §6.3):** while the full suite runs in <~60s, run it
fully at every covenant — it already does (14 packages, ~2.5s each in
parallel). When it crosses ~60s, `covenant.sh`/`covenantwin.py` switches to
tiered selection automatically (TIER 1/2/3 per Guide §6.3); CORE_FILES always
gets transitive-closure selection at Tier 2 and mandatory Tier 3. The
threshold is enforced by the ledger (`covenant_state.json`), not memory.

**Quarantine:** `quarantine.txt` (committed, currently empty) holds flaky
tests with a linked issue — never deleted, never retried-until-green. A
quarantined test covering a CORE_FILES module is a hard stop (§2.2 table).

**Browser/E2E layer (Guide §6.2):** not applicable. RaceVeil has no frontend,
routing, or rendering surface — it is a CLI binary. If a future phase adds a
web UI or dashboard, this section is revisited via human PR at that time, not
inferred.

## 7. PHASE 2 — Design Declaration Requirements (Guide §3.2.1)

Before Phase 3 (implementation) begins on any `/feature` task, declare:

```
GOAL:  <concrete, observable outcome>
VERIFY: <specific test/command that confirms it — not "tests pass" generically>
```

If multiple reasonable interpretations exist and one must be picked to
proceed without a full stop:

```
ASSUMING:    <the interpretation being proceeded on>
ALTERNATIVE: <what would change if this is wrong>
```

This is a declaration, not a question — it does not block Phase 3. Reserve a
genuine STOP-and-ask (via a blocking question mechanism, §8 below) for cases
where no interpretation is reasonably safe.

**Scope Discipline** (Guide §2.5.6a) runs during Phase 4 (Verification Loop),
**before** the checkpoint write — not after the diff is already staged:
minimum footprint (no abstraction for a single call site, no unrequested
configurability, no error handling for unreachable states) and surgical
boundary (every changed line traces to the stated task; no drive-by
reformatting; pre-existing dead code is named, not touched, unless the task
asked for it).

## 8. Blocking Questions (Guide §2.5.6b)

Every hard stop (§2.2 table) and every genuine scope fork is surfaced via
`AskUserQuestion` (this environment's structured, blocking question
mechanism) — never as a sentence buried inside recon output, a diff summary,
or test results. A question a human can scroll past is not a safeguard. This
mirrors the PUSH CONFIRMATION discipline in §9 below: each blocking question
stands on its own; a prior, unrelated approval never covers a new decision
point.

## 9. THE COMMIT/PUSH COVENANT (hook-enforced, ledger-aware — Guide §5.3)

Two layers: the model orchestrates and explains; `.githooks/pre-commit` and
`.githooks/pre-push` (via `covenantwin.py`) enforce mechanically regardless of
what the model does or forgets.

```
STEP 1 — /audit    Ledger hit at current fingerprint -> SKIP loudly.
                    Else: audit the change set. ANY finding blocks
                    (no baseline). CRITICAL/HIGH -> await human via
                    AskUserQuestion. MEDIUM/LOW -> auto-fix, re-verify.

STEP 2 — /review   Ledger hit -> SKIP loudly. Else: layer compliance per
                    changed file, secrets-in-diff grep, coverage check,
                    go.mod diff assertion (any dependency change without
                    prior hard-stop approval = HARD STOP).

STEP 3 — git        Only if 1 and 2 pass.
                    git update-index -q --refresh; git diff --no-ext-diff
                    git add <specific files — NEVER git add -A>
                    Conventional Commit (feat|fix|refactor|test|perf|
                    security|docs|chore(scope): imperative description).
                    pre-commit hook re-verifies mechanically.

STEP 4 — PUSH CONFIRMATION (mandatory, no exceptions)
                    State exact branch + remote in chat. Wait for explicit
                    human approval IN THIS CONVERSATION via AskUserQuestion
                    or an unambiguous chat reply. A prior "push" mentioned
                    earlier in the same message does NOT count. No reply =
                    no push, ever. The pre-push hook independently refuses
                    protected branches, +refspec force syntax, missing
                    receipts, and expired SKIP_COVENANT bypasses.
```

Atomic commits: one logical change, suite passes at that commit alone,
reviewable in under 5 minutes, message explains WHY. Layered commits for
multi-layer features: one commit per layer (domain -> infrastructure ->
application -> presentation -> tests), each independently bisectable.

## 10. CHECKPOINT SYSTEM (Guide §4.1)

Storage: `.claude/checkpoints/<YYYYMMDD-HHMM>-<phase>.md`, always mirrored to
`.claude/checkpoints/LATEST.md` (gitignored, 10 most recent kept).

Trigger rules — evaluate at every `/feature` phase boundary (end of Phase 1,
3, 4) and after any `/audit` or `/review`; write BEFORE continuing if pressure
is HIGH (any of C1-C5), and ALWAYS at end of Phase 5:

```
C1. 3+ pipeline phases completed this session
C2. 5+ files modified this session
C3. A hard stop fired and was resolved this session
C4. A test failure was diagnosed and fixed this session
C5. Session older than ~2 hours
```

Schema (every field required — Guide §4.1's exact fields: phase, git_sha,
branch, dirty_files, timestamp, TASK, FILES MODIFIED THIS SESSION, DECISIONS
LOCKED, CURRENT STATE, PENDING, RESUME INSTRUCTION). Post-commit update is
mandatory, not optional, on every successful `git commit` — before any push
attempt.

Resume protocol at session start: if `LATEST.md` exists, read it, compare its
`git_sha` to `git rev-parse HEAD`. Match -> announce "Resuming from checkpoint
<ts>" and execute the RESUME INSTRUCTION. Diverged -> state the divergence,
ask. Clearly new task -> ignore.
